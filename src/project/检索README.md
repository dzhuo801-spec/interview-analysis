# 检索

## 一、这是什么

1. 读哪张表：`output\访谈标签表_归并.csv`（90 行 × 7 列）
2. 能按什么查：关键词 / 细标签（22 种）/ 大类（7 种）
3. 输出什么样：命中数 + 前 3 条带【id · 说话人】出处

## 二、设计动机 —— 三条证据

1. 标了「婚俗变迁」的有 **11** 条，其中 **3** 条原文里根本没出现“婚俗”（用的是“结婚”“摆酒”）。
   所以按关键词查会漏这 3 条，按标签查又看不出它到底在讲什么 ——
   **两条路都需要，而且必须带出处，让人能回到原文核对。**

2. 标了「变化」的 6 条，原文全是「年轻人出去打工以后回来就不太一样了」；
   标了「变迁」的 4 条，原文全是「村里的老人越来越少见了」。
   光看标签名，完全无法判断它讲的是打工还是老人 ——
   **所以归并必须看原文，不能按标签名归**：这就是为什么「变化」进了生计，「变迁」进了人口。

3. 90 行里只有 **22** 种不同句子。
   同一句话被多个人说过，所以检索结果会大量重复 —— 要么按句子去重，要么按说话人聚合再看。
   这也说明语料是构造的，检索这部分练的是**流程**，不是内容量。

## 三、为什么归并表放 csv，不放代码

- 方便查看：22 行两列，用 Excel 就能审，别人不用读代码也看得懂。
- 分类标准会变（今天 22 → 7，以后可能 22 → 9）。放 csv 里，**改分类只改数据，代码一行不动**。

## 四、怎么跑 + 产出物

```
.venv\Scripts\python.exe src/project/检索.py
```

| 文件 | 内容 |
|---|---|
| `src/project/检索.py` | `retrieve(关键词, 主题, 大类)` |
| `src/project/主题归并.py` | 22 → 7 类归并 |
| `output/主题归并表.csv` | 22 行映射表 |
| `output/访谈标签表_归并.csv` | 90 × 7，多了「主题归并」列 |
